# making-cage

본 길이(스켈레톤 변형)에 대응하는 저폴리곤 cage 생성. mesh deformation의 전 단계.

## 의도 (goal)

- `mapping_tester`의 `import()` 시점에 rest pose에 맞춘 rest cage를 생성하고, 본 길이를 조정할 때마다 본 위치에 맞춰 cage를 업데이트한다.
- 이를 위한 cage 생성 함수는 **편집 가능한 상수 외엔 뼈 길이 목록만**을 파라미터로 받는다(매 프레임 메시 버퍼를 읽지 않음). cage가 갖춰야 할 조건:
    - 메시를 완전히 포함한다.
    - 메시에 가급적 fit해야 한다.
    - 지나치게 복잡해선 안 된다. 모든 기둥은 사각이면 충분하다.
    - 제어점(cage 버텍스)이 본 길이를 반영한다. 1단계는 t-pose 팔다리의 시작·끝 정도면 충분(길이 반영 목적).
- 알고리즘 최초 작성 시 rest 메시 정보(머리 크기, 팔다리 굵기 등)를 참조해 상수화한다. 현재 vicon 메시에 대한 rest cage가 조건을 만족하면, 변형된 비율의 pose에 대한 cage도 만족할 것으로 본다.
- mesh deformation은 이 단계에서 다루지 않는다.

## 구현 (implemented)

파일: [cage.cs](../unity/Assets/Scenes/cage.cs), [mapping_tester.cs](../unity/Assets/Scenes/mapping_tester.cs).

케이지는 **의도적으로 조악한 단일 폐쇄 껍질**이다. 축 정렬 사각 링 7개(28정점 / 52삼각형)뿐이며,
deform에 케이지 모양이 어떻게 반영되는지 눈으로 읽을 수 있는 최소 형태다.

- **기준 링 7개** — 모두 사각(제어점 4). `n`(법선)은 몸 바깥을 향하므로 링의 한 변은 **`n` 방향으로 가장 먼 앵커**에 놓인다(→ 그 쪽 다리의 더 낮은 관절, 더 먼 손끝). 사각형 크기는 앵커들의 퍼짐 + baked 여유.
    - **좌우 두 변은 각자의 앵커로 독립 배치된다.** 양다리 공용 링(무릎·발바닥)에서 이게 중요하다. 두 변이 하나의 평면을 공유하면(=`n`으로 전체 최댓값) 한쪽 다리만 **줄일** 때 링이 반대쪽 무릎에 붙잡혀 따라오지 않는다(늘일 때만 따라옴). 변을 갈라 두면 링이 **기울면서** 양다리를 모두 추적하고 포함도 유지한다. 대가는 이 링만 비대칭 편집 시 축 정렬이 풀리는 것 — 깊이 범위는 좌우 공유라 네 점은 항상 한 평면에 남는다.
    - 한쪽 팔다리에만 걸린 링(정수리·팔꿈치·손끝)은 같은 앵커가 양쪽 변에 들어가므로 축 정렬 그대로다. 좌우 분리는 앵커의 rest 실루엣 좌표(중앙 기준)로 bake에서 자동 결정된다.
    - **정수리** — `Head`에서 파생. 머리 살 위로 밀어낸 수평(⊥up) 링. 캡(실제 판).
    - **좌·우 팔꿈치** — `*ForeArm`(팔꿈치 관절)에 놓인 ⊥side 링. 그 평면을 지나는 살만으로 두께 측정.
    - **좌·우 손끝** — 가장 먼 손가락 뼈에서 파생. 손 살 밖으로 밀어낸 ⊥side 링. 캡.
    - **양무릎(단일)** — `LeftLeg`+`RightLeg`. **더 낮은 무릎**에 놓인 ⊥up 링, 두 다리를 함께 감싼다.
    - **양 발바닥(단일)** — 양 `*Foot`/`*ToeBase`. **더 낮은 발** 살 아래로 밀어낸 ⊥up 링. 캡.
- **여유(reach)** — 링은 자기 살만 보므로 얼굴·가슴·배·엉덩이·어깨는 판 안쪽에 들어오지 않는다. 링별로 여유를 씬 단위로 더한다: 깊이 축은 `front`/`back`(모든 링에서 `+depth`가 앞), 실루엣 축은 `hi`(팔꿈치·손끝 링에선 위, 나머지에선 캐릭터 왼쪽). 현재 **정수리 앞 +0.1 / 좌우 팔꿈치 앞 +0.2·뒤 +0.1·위 +0.05 / 양무릎 뒤 +0.1**. 편집 가능한 상수이며 bake에서 native 단위로 환산된다.
- **판(panel)** — 링 제어점을 이은 평면 판. 앞판 = 몸통 8각형(정수리↔팔꿈치↔양무릎) + 팔 2 + 다리 1, 뒷판은 그 거울. **옆판은 실루엣 둘레 간선마다 1쿼드(14개)**, 그중 4개가 정수리·손끝·발바닥 링 자신 = 캡. 결과는 워터타이트(Euler = 2).
    - 삼각화는 fan이 아니라 **좌우 실루엣 사슬 사이의 ladder(strip)**. 링마다 깊이가 다르므로 fan은 판 전체를 첫 제어점 기준으로 비틀어, 몸통 중앙선이 정수리에서 무릎으로 직행하며 **팔꿈치 링을 건너뛴다**(= 팔꿈치 앞 여유가 가슴에 반영되지 않음). ladder는 좌우 대칭이고 가슴 띠가 팔꿈치 깊이로 평평하게 나온다.
- **축** — rig root 로컬 공간은 월드 정렬이 아니므로 `up`(Hips→Head), `side`(Right→LeftArm), `depth`(외적)를 rest 스켈레톤에서 유도하고 각각 **cardinal 축으로 스냅**해 축 정렬을 유지한다. 외적은 깊이 축만 정하고 **어느 쪽이 앞인지는 정하지 못하므로 발가락(Foot→ToeBase)으로 부호를 정한다** → `+depth`가 앞.
- **bake(에디터, 1회)** — `cage.bake(source)`가 rest 스켈레톤 + rest 메시에서 상수(`cage_constants`)를 산출해 직렬화. `import()`에서 호출.
    - 스켈레톤 전체를 FK 대상으로 열거(손가락 포함) → 링 앵커를 손가락 뼈까지 자유롭게 지정 가능.
    - 각 정점을 지배 본에 배치하고, 링별로 지정된 **서브트리의 살**만 측정. margin(5%)으로 여유 확보.
    - 판 방향은 일관되게 추적하되 어느 쪽이 바깥인지는 rig 축에 달렸으므로, **부호 있는 부피**로 판정해 필요 시 전체 winding을 뒤집는다. 링 슬롯 표의 오추적은 **닫힘·정합 assertion**으로 즉시 드러난다.
- **build(런타임, 순수)** — `cage.build(lengths, k)`. 본 길이로 FK 재구성 → 링을 앵커에 재배치 → 고정 토폴로지 메시.
    - FK: `pos[j] = pos[parent] + rest_dir[j] * length[j]`. rest 방향은 길이 편집에 불변이므로 라이브 스켈레톤과 정확히 일치. 편집 대상이 아닌 본(손가락·발가락)은 rest 길이 사용.
- **통합** — `mapping_tester`: `import()`가 bake + cage 자식 생성 + `update_cage()`. 슬라이더/리셋 시 `update_cage()`로 재생성. cage는 rig root의 identity-local 자식이라 씬 스케일(x100)을 상속.
- **읽기 설정** — 정점 스캔을 위해 `ViconActorFingers_orient_finger_fixed.fbx`의 Read/Write(`isReadable`)를 활성화.
- **디버그(에디터)** — 인스펙터 버튼 + `OnDrawGizmosSelected`(선택 시), 모두 변형된 cage 공간에서:
    - `check containment` → 소스 지오메트리를 **타깃 본에 LBS 스킨**한 정점을 **현재 cage**와 비교, 벗어난 정점을 빨간 큐브로. 케이지가 폐쇄 껍질이므로 판정은 **광선 패리티**(교차 홀수 = 내부).
    - `check self-collision` → 정점을 공유하지 않는 **케이지 삼각형끼리의 관통** 검출, 해당 삼각형을 빨간 외곽선으로. 링 순서가 유지되는 한 rest에서 0.
    - 지오메트리는 항상 readable한 소스에서, 본은 타깃에서 읽음(둘은 동일 토폴로지·본 순서 클론).

## 향후 과제 (future)

- **포함률**: 이 정도로 조악한 케이지는 메시를 다 담지 못한다(어깨·배·엉덩이·팔 위아래가 판을 뚫는다). 의도된 1단계 상태이며, `check containment`가 그 양을 그대로 보여준다. mesh deformation이 들어오면 메시가 케이지를 따라가므로 이 수치의 의미가 달라진다.
- **mesh deformation**: cage 기반 정점 사상(별도 조사 [cage-deformation-plan.md](cage-deformation-plan.md)). Green coordinates는 바깥 법선이 필요하므로 위의 winding 판정이 전제 조건이다.
- (선택) 필요해지면 링을 추가(어깨·골반·가슴)해 실루엣을 조이는 방향으로 확장. 토폴로지 표만 늘리면 되고, assertion이 오추적을 막아준다.
