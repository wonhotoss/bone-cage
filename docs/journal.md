- Unity를 밖에서 돌릴 수 없어 컴파일은 `dotnet build unity/Assembly-CSharp.csproj`(임시 출력 경로), 토폴로지는 표를 파이썬으로 재현해 닫힘·Euler 검사. containment·deform은 에디터에서 사람이 확인.

**2. 정중선 (`e12d603`)** — 한쪽 겨드랑이를 당기면 반대편이 끌려오는 비국소성과, 앞으로 넣을 V넥 모두 정중선 정점을 요구했다. 국소로는 불가능: 판 변 위의 정점은 그 변을 공유하는 양쪽 판에 다 들어가야 닫힘 assertion을 통과하므로, 정중선은 crown → hip → knee → sole을 관통하는 사슬이 된다.
- 프리미티브는 6점 링이 아니라 **정중선 기둥(post)**. 손의 `cage_post`가 이미 "아핀 앵커 + d 축 정점 2"였고, 링 번호 규칙·토폴로지 표(링 변과 기둥을 섞어 씀)·옆판이 그대로 남는다.
- 기둥의 `center` 하나를 **d 앵커 두 세트**로 일반화 — 링 변과 같은 규칙(max/min + 여유). sole 앞변은 ToeBase가 정하므로 중심 관절 하나로는 발 길이 편집 때 mid가 변에서 떨어졌다.

- 비국소성: 반대편으로 어느 정도 전이되지만 자연스러운 수준. MVC 가중치가 전역이라 완화일 뿐 — 해결은 좌표계(Green/Somigliana) 쪽.

**3. 라글란 arm 링 + V넥 (`5c31219`)** — arm 링 윗변을 몸통 안쪽·위로 들여 승모근 위에 얹고, 아랫변을 겨드랑이 속으로. 팔 판이 라글란 소매가 되어 삼각근이 소매 안에 들어가고, 두 윗변과 Neck 위의 `neck mid`가 앞뒤로 V를 이룬다.
- 기존 몸통 반판(crown·hi–hip·hi 현이 세로 가로대)은 승모근 점이 현 안쪽에 들어와 **접힌다**(닫힘은 유지, 표면이 겹침). 판을 V에서 잘라 몸통 반판은 `arm·hi → arm·lo → hip·hi → hip·mid → sternum → neck`, 머리 반판은 V → crown. 양쪽 볼록.
- 가로대를 가로로 눕히려면 실루엣 점마다 정중선 점이 필요 → 겨드랑이 높이에 `sternum mid`(Spine3, y 0.402 ≈ 겨드랑이 0.40). 5각형은 ladder가 못 채운다.
- 링은 변별 `along`(outward hi/lo)을 얻었고, 이어서 변별 s 여유(`lo` 신설)와 **코너별** 깊이 여유(`hi_front, hi_back, lo_front, lo_back`)까지. 두 변이 `d`에 평행이라 네 코너는 여전히 한 평면 — N1의 "깊이 공유라 평면" 근거는 "변 평행이라 평면"으로 고쳤다.
- neck/sternum mid는 자기 가로대의 arm 변 깊이를 따른다 → V–겨드랑이 가슴 띠의 앞뒤는 arm 링 hi/lo front/back으로 조절.
- 승모근 점은 어깨 관절에 고정 오프셋 → 쇄골 편집을 100% 따라가는 근사. 절반이어야 하면 아핀 기둥으로.

**4. 머리–목 분리 링 (`77974a1`)** — 턱끝이 Head 관절보다 앞·아래에 있어 분리 평면은 기울어져야 한다. 씬에 놓아둔 **head splitter** 평면을 Hips 공간으로 환산: 타깃 rig root 월드 (2,0,0)·−90° x·×100, Hips 로컬 +90° x → Hips 공간 = 월드 축. 평면 법선 (0, .906, .423) = `side` 축 25°, Head에서 법선 방향 0.023 m.
- `head` 링: `n = up↷25°`, `d = depth↷25°`, `s = side`, outward 0.023. 링 코드는 프레임이 직교면 되므로 기울어진 링도 같은 코드.
- 측정 종류 **split** 신설(`bool terminal` → `enum fit{ joint, cap, split }`): 평면은 앵커 + outward에 고정, 단면은 평면 너머 Head 살 전체 — 머리 판이 감싸야 할 것. crown과 비슷한 값이 나오지만 종속은 아니다.

- `hip` 링 → **`spine` 링**(Spine 관절, joint, 허리). 몸통 반판의 아랫변이 `spine·hi → spine·mid`.
- 골반은 링이 아니라 **기둥 3**: `crotch`(Hips − up·drop), `L/R hip`(앵커 (UpLeg, Hips) 가중치 (1+f, −f) + up·f·drop = `UpLeg + f·(UpLeg − crotch)`). 손가락 endbone과 같은 수법이라 고관절 폭 편집에 (1+f)배로 따라 나간다. 셋이 골반 살(Hips·양 UpLeg 본)의 depth 구간 하나를 공유(d 앵커 Hips) — 손의 판 두께처럼.

**2. 발 (`a982e22`)** — sole 삭제, 다리별 `knee → ankle → toe → tip`.
- **ankle**: Foot 관절을 지나되 **뒤로 기울어진** 링(`n = −up↷tilt`, `d = depth↷tilt`, 초기 45°). 수평이면 뒤꿈치 아래와 발등 위를 동시에 자르지만, 뒤꿈치 바닥에서 발등–정강이 연결부로 기울이면 종아리 관과 발 관을 가르는 자연스러운 단면. wrap = LeftLeg 서브트리, joint slab.
- **toe**: ToeBase에서 `n = depth, d = up` 세로 링 — front = 발등, back = 발바닥.
- **tip**: 관절 없는 endbone 위의 **기둥 쌍**(`(1+f, −f)`·(ToeBase, Foot), f = 발가락 살이 ToeBase 너머로 뻗은 길이 ÷ 발 뼈) — 발 길이에 비례해 따라 나가는 뚜껑. 캡 = `tip·hi → tip·lo` 쿼드 1.
- 프레임의 `d`가 knee(depth) → ankle(depth↷45°) → toe·tip(up)으로 연속해서 돌아 **앞판 = 정강이 → 발등 → 발가락 위, 뒷판 = 종아리 → 뒤꿈치 → 발바닥**. 링 코드는 그대로(직교 프레임이면 됨). `[N14]`.

**6. 좌우 거울 대칭 삼각화 (`f7c4923`)** — 골반·허벅지에서 좌우 토폴로지가 다르게 보였다. 조사 결과 정점과 ladder 가로대는 이미 대칭이고 **쿼드 대각선만** 달랐다: ladder는 대각선을 항상 `v[i]–v[j−1]`로 긋는데, 오른쪽 판은 왼쪽 판의 거울상을 **역순**으로 추적하므로(거울은 방향을 뒤집어 winding을 지키려면 역순) 다른 코너를 잇는다. 뒷면도 앞면 고리의 역순이라 같은 일이 생겨, 케이지는 거울 대칭이 아니라 **up 축 180° 회전 대칭**(왼 앞판 ≡ 오른 뒷판의 거울)이었다. 비평면 쿼드에서는 표면이 달라 대칭 메시의 containment·MVC 가중치가 좌우 다르게 나온다.
- 답: `strip(loop, flip)` — `flip = 거울면 XOR 뒷면`이면 반대 대각선. 좌우가 정확한 거울이 되고, 쿼드가 앞/뒤 같은 두 제어점을 잇는 선으로 접힌다. 거울면 판정은 면의 rest 중심 `side` 부호(정중선에 걸치는 면은 assertion — N10 덕에 없다). 표·recipe 변경 없음. 손도 같은 규칙(`mirror` 역순 추적이 같은 문제를 갖고 있었다).
- 검증: 파이썬으로 몸통 192면의 삼각형 집합이 정점 거울 매핑(+winding 반전) 아래 닫힘(차집합 0); 기존 규칙은 차집합 376.

## 2026-09-07 (이어서) — 두께 driver의 시험대: 체형 슬라이더와 4층

커밋: (이 항목). 룰은 아직 하나도 없다.

### 왜 룰보다 시험대가 먼저인가
스윕의 세 층은 뼈를 **서로 독립으로** 흔든다 — 단독, 쌍, 그리고 53개 독립 무작위. 그런데 두께 driver가 겨냥하는 것은 `전신 1.3배` 같은 **상관된** 변화이고, 53개가 동시에 같은 값이 될 확률은 사실상 0이다. 즉 지금까지의 스윕은 driver가 고칠 것을 재고 있지 않았다.

### 체형 슬라이더 다섯
계층에서 그대로 유도된다. 뼈 이름을 나열하지 않고 서브트리 넷(`L/R Arm`, `L/R UpLeg`)만 이름한다.

| | 유도 | 개수 |
|---|---|---|
| torso | 전체 − arms − legs | 9 (척추4 · 목2 · 머리1 · 어깨밑동2) |
| arms | 쇄골 서브트리 ×2 | 36 |
| legs | 고관절 서브트리 ×2 | 8 |
| left | `LeftArm` ∪ `LeftUpLeg` 서브트리 | 22 |
| right | 거울 | 22 |

`torso + arms + legs = 53`으로 **완전 분할**이고, `left + right = 44 = arms + legs`로 사지를 다시 좌우로 가른다. 어깨밑동이 좌우에서 빠지므로 **몸통은 어떤 비대칭에서도 통째로 남는다**. 뼈가 받는 값은 덮는 슬라이더의 곱이다(왼팔 = arms × left).

슬라이더를 옮기면 **지난 값과의 비만** 곱한다 — 그래서 그 아래의 개별 본 편집이 살아남고 두 절을 어느 순서로 써도 된다. `reset bone lengths`가 다섯을 1로 되돌린다.

비대칭은 보정이 이미 처리한다: 네 보정의 바닥이 전부 `Max`라 **높은 쪽이 이기고** 머리·허리 가로대가 통째로 올라간다. 기울지 않는다.

### 스윕 4층 — 그리고 뜻밖의 결과
torso·arms·legs를 {0.7, 0.85, 1, 1.2, 1.4}, left·right를 {0.9, 1, 1.1}로 훑는 격자 1,125.

| | 3층 (무작위 20,000) | **4층 (비례 1,125)** |
|---|---|---|
| 실패 | 0 | **0** |
| 새는 케이스 | 11,448 (57%) | **274 (24%)** |
| 탈출 중앙값 / 90th / 최악 | 8 / 30 / **96** | 8 / 15 / **22** |

| 케이스 | 탈출 |
|---|---|
| 항등 (전부 1) | **0** — 4층이 옳게 돌고 있다는 확인 |
| torso 1.4 단독 | **0** |
| arms 1.4 단독 | **0** |
| legs 1.4 단독 | 14 |
| 균등 1.4 | 11 |

**실제 비례에서는 잴 실패가 거의 없다.** 3층의 `Hips` +96은 어떤 몸도 도달하지 않는 조합이 만든 것이었다. 그래서 **두께 driver는 수치를 고치는 작업이 아니라 설득력을 바꾸는 작업**이다 — 룰의 근거는 탈출 수치가 아니라 "전신을 1.2배 늘여도 팔 굵기가 그대로"라는 눈에 보이는 사실이고, 탈출은 상한을 넘지 않았는지 보는 보조 지표로만 쓴다.

### 룰을 넣기 전에 선언한 것 (§9)
- **rest는 항등** — 모든 driver는 `f(1) = 1`. 그러면 bind와 지금까지의 측정이 그대로 유효하다.
- **자기겹침 0이 상한** — 단면을 키우면 팔 링이 몸통에, 무릎 링이 서로 닿는다. 룰마다 스윕을 다시 돌린다.
- **신호는 탈출, 다만 약하다**(위).
- **마지막은 눈** — 목표가 설득력이므로 에디터에서 본다.
- **driver는 gate보다 앞** — gate는 자기가 판정한 좌표가 뒤에 바뀌지 않는다는 전제 위에 선다. `양 고관절 0.5 + 양 허벅지 1.5`에서 무릎 링 ×1.5로 재면 driver → gate는 안쪽 변 +0.50 cm, gate → driver는 **−2.97 cm**로 다시 정중선을 넘는다. 단면 배율은 배치의 항이지 보정 뒤의 패스가 아니다.
- **지금 gate 여유 넷은 driver 없는 폭에 튠된 값**이므로 driver가 들어오면 함께 다시 본다.

## 2026-09-07 (이어서) — 선언은 도착하는가: 전달비 probe, 그리고 좌표계 판단의 반전

커밋: (이 항목).

### 물음
두께 driver는 "이 구간의 단면 = rest × f(뼈 길이 비)"를 **선언**하는 일이다. 값을 정하려면 먼저 알아야 할 것이 있다 — **그 선언이 살에 얼마나 도착하는가.** 그래서 스윕 도구에 `--probe k`를 붙였다: 뼈를 전부 rest에 두고 한 구간의 단면 여유를 ×k 한 케이지로 rest 메시를 사상한 뒤, **bake가 쓰는 그 측정 창**에서 살의 폭·깊이를 다시 잰다. `전달비 = (메시 비 − 1) / (케이지 비 − 1)`.

### 첫 결과가 틀렸다 — 나비 단면
처음 probe는 **링의 여유만** 곱했다. 그러자 깊이 전달비가 spine −0.01, spine1 0.18, crown **−0.31**, head 0.02로 나왔고 나는 그것을 "케이지의 비단조 응답"으로 보고했다. **틀렸다.**

정중선 기둥이 제자리에 남아 있었다. rest에서 spine 링의 앞변과 `spine mid`의 앞끝은 **정확히 같은 깊이**인데(§3b가 그렇게 선언한다), 링만 넓히면

| | 링 앞 | 정중선 앞 | 차 |
|---|---|---|---|
| rest | +15.69 | +15.69 | **0.00** |
| ×1.2 | +18.83 | +15.69 | **3.14 cm 함몰** |
| ×1.5 | +23.53 | +15.69 | **7.84 cm 함몰** |

위에서 본 단면이 **나비**가 된다. 두꺼운 몸이 아니다. 링과 그 위의 정중선 기둥을 함께 곱하도록 고치자 깊이가 spine **0.99**, spine1 **1.01**, crown **0.92**, head **0.83**으로 올라갔다 — 이상값이 거의 전부 probe의 결함이었다.

### 고친 뒤의 결과 (×1.2, 모든 구간)

| 구간 | 폭 / 깊이 |
|---|---|
| L elbow | **1.00 / 1.00** |
| L knee | **1.03 / 0.99** |
| spine1 | 0.99 / **1.01** |
| spine | 0.95 / **0.99** |
| crown | 0.95 / 0.92 |
| head | 0.72 / 0.83 |
| L arm | 0.83 / 0.86 |
| L ankle | 1.00 / 0.54 |
| L toe | 0.98 / 1.41 |
| L wrist | 0.64 / 0.05 |

- **구간의 제어점이 전부 함께 움직이면 0.92 ~ 1.03.** 선언이 손실 없이 도착한다.
- **k에 대해 선형이다** — 0.8 · 1.2 · 1.5에서 같은 값(팔꿈치 1.00/1.00/1.00, 무릎 1.03/1.03/1.03, spine1 0.99/0.99/0.99). driver는 보정표 없이 비율을 그대로 쓸 수 있다.
- **낮은 행은 전부 "아직 안 따라온 이웃"이다**: 손은 처음부터 끝까지 기둥(손목 깊이 0.05), `tip` 기둥과 평평한 발바닥 구속 `[N14]`(발목 0.54 · 발볼 1.41 과응답), arm 링의 띠에 선 `neck mid`·`sternum mid`와 `delt`(arm 0.86). 좌표계 손실이 아니라 **구간 소속의 문제**다.

### 그래서 driver의 단위는 구간이다
링 네 코너 + 그 위에 선 기둥이 **한 배율**을 받는다. gate가 "변 하나가 아니라 링 전체를 멈춘다"였던 것과 같은 종류다. 기둥의 깊이는 §3b가 링에서 유도한다고 선언하지만 bake는 독립 상수로 굽는데, **driver가 구간의 제어점을 전부 곱하는 쪽**으로 정했다 — 런타임에 다시 유도하면 방금 `[N16]`에서 걷어낸 "제어점이 서로를 읽는다"가 되살아난다.

### 좌표계 판단이 뒤집혔다
[cage-deformation-plan.md](cage-deformation-plan.md)는 "형상·두께 보존 → 순수 정점 결합 부적합, 면 법선 항 필수 → Green 1차, Somigliana 목표"로 적혀 있었다. 그 전제는 **두께를 좌표계가 공급한다**였다.

이 시스템에서 두께는 **케이지의 일**이다. 근거가 기하학이 아니라 해부학이고, 부위마다 다르며, 판단 기준이 시각적 설득력이라 "두께"라는 한 마디로 묶이지도 않는다. 좌표계에 바라는 것은 그 선언을 정직하게 옮기는 것뿐이다.

- **MVC는 linear precision**을 가져 케이지의 아핀 변화를 정확히 재현한다 — 케이지가 유일한 저자로 남는다.
- **Green은 닮음만 정확히 재현하고 이방성 stretch를 등방 팽창으로 바꾼다.** 좌표계가 자기 몫의 두께를 얹으므로 driver 값이 "원하는 두께 − Green이 준 몫"이 되고, 그 몫은 부위마다 다르다. **틀린 선택이다.**
- 위 측정이 이를 뒷받침한다: 손실이 없으므로 바꿀 이유도 없다.
- **MVC의 실제 약점은 두께가 아니라 오목부의 음수 가중치와 비국소성**이다(`[N18]`). 문제가 되면 **PMVC/QMVC** — 음수 가중치만 없애고 순수 정점 결합의 성질을 지키며 두께를 얹지 않는다. Green 이식 계획은 철회하고 기록으로 남겼다.
- 참고로 bind 크기(제어점 236 · 면 468 · 정점 36,426, float32): MVC 34 MB · Green 103 MB · Somigliana 920 MB.

### 남긴 일
- **첫 driver 룰.** 단위는 구간, 형태는 §3 표의 열, 자리는 gate보다 앞.
- arm·손·발의 구간 소속을 driver 열에 어떻게 적을지 — 이름이 링에 매이지 않은 기둥들(`neck mid`·`sternum mid`·`delt`·`tip`·손 기둥)이 그 대상이다.
- `joint_centers`를 public으로 열었다(probe가 관절 중심을 읽는다). §1이 이미 선언한 함수라 노출만 한 것이다.

## 2026-09-07 (이어서) — 첫 driver 룰: 몸통 폭은 고관절과 어깨를 따른다

커밋: (이 항목). 씬은 별도로 — `rebuild cage` 뒤.

### 룰
`spine`·`spine1`·`spine2` 링의 `s` 여유(폭)에 `lerp(고관절너비 / rest, 어깨너비 / rest, w)`를 곱한다. 고관절너비 = `|LeftUpLeg − RightUpLeg|`(rest 20.10 cm), 어깨너비 = `|LeftArm − RightArm|`(rest 32.94 cm). `w`는 링마다 튠, 초기 0.5. 의도 둘 — 아래 링은 고관절을, 위 링은 어깨를 더 따른다; 척추 마디가 길어져 링이 오르내려도 **자기 폭을 가지고 간다**.

### 절대형에서 비율형으로
처음 안은 `lerp(고관절너비, 어깨너비, w) + offset`이었다. 그러면 초기값에서 rest 폭이 잰 값이 아니라 두 너비의 평균이 되어 **rest 케이지가 바뀌고**, 살을 다시 담으려면 offset을 링마다·메시마다 튠해야 한다 — §9에 방금 선언한 첫 불변식(rest는 항등)을 깨고, 그래서 "링 정의 변경에 가깝다"고 느껴졌던 것이다. 비율형은 rest에서 두 비가 1이라 rest가 그대로고 offset이 필요 없으며 다른 메시에도 재튠 없이 붙는다. 절대형이 더 잘하는 것은 몸통 폭을 메시에서 완전히 떼어내는 것 하나뿐이다. **비율형으로 확정.** 그래서 이것은 §3 레시피 변경이 아니라 **driver 열**이다 — §3 표의 `width` 열, `ring_corners`에서 `s_hi`·`s_lo`에 곱해지는 항, gate 앞.

### 일반 형태
`width = {(관절 a, 관절 b, 가중치)…}`, Σ가중치 = 1, 비 = Σ 가중치 · |jc[a] − jc[b]| / rest 거리. 뼈 길이도 관절 쌍(자식, 부모)이므로 다음 룰이 같은 열을 쓴다. 코드는 `recipe.width`(선언) → `cage_ring.width_a/b/weight/rest`(bake) → `ring_corners`(평가). `s`만 건드리고 깊이는 잰 값 그대로다 — 정중선 기둥은 `side`로 움직이지 않으므로 어제 본 나비 단면이 여기서는 생기지 않는다.

### 형식 검산 (rest 상수로)

| 케이스 | spine | spine1 | spine2 | L knee |
|---|---|---|---|---|
| rest | 32.70 cm (×1.000) | 24.88 (×1.000) | 28.62 (×1.000) | 13.90 (×1.000) |
| 양 고관절 ×1.2 | ×1.100 | ×1.100 | ×1.100 | ×1.000 |
| 양 쇄골 ×1.2 | ×1.100 | ×1.100 | ×1.100 | ×1.000 |
| 둘 다 ×1.2 | **×1.200** | ×1.200 | ×1.200 | ×1.000 |
| lumbar ×1.5 (링이 오름) | **×1.000** | ×1.000 | ×1.000 | ×1.000 |

rest 항등, `w = 0.5`의 lerp 그대로, 링이 올라가도 폭 불변, 구동하지 않는 링 불변.

### 스윕 (driver를 오늘 상수에 주입해 컴파일된 경로로; Unity 재bake 전)
`--probe 1.2` 표가 driver 전과 자리까지 같다 — rest에서 factor가 정확히 1. 1·2·4층 2,321 케이스 **실패 0**, rest 0/0.

### 왜 지금인가
다음 룰이 arm 링을 쇄골 비로 키우는 것인데(§9 두께 driver), 링의 실루엣이 "잰 살 + 여유 넷(`hi`·`lo`·`outward hi`·`outward lo`)"이면 곱할 대상이 다섯이고 그중 넷이 절대값이다. 절대 여유가 비율 아래서 어긋나는 것은 이미 한 번 겪었다(`arm outward hi = −0.05`가 쇄골을 줄이면 정중선을 넘던 것, §9 자기겹침 지도 쇄골 무리). 곱할 것이 하나여야 한다.

### 정의
정면에서 arm 링은 Arm 관절을 **중점**으로 지나는 선분이다. 위끝이 안쪽으로 `arm tilt`만큼 기울고(라글란), 길이가 `arm length`다. 양끝이 그대로 두 변이다:
`s_hi = s_lo = (L/2)·cos θ`, `along_hi = −(L/2)·sin θ`, `along_lo = +(L/2)·sin θ`.
깊이는 그대로 관절 창의 살에서 재고, hi/lo 변별 `front`·`back` 여유 넷은 남긴다 — 정중선 기둥 둘이 이 깊이를 띠로 쓰고 있어 `[N17]`, 이번에 건드리지 않는다.

코드로는 `measure` 뒤에 두 링의 `s_hi/s_lo/along_hi/along_lo`를 덮어쓴다 — 손목 링을 손이 덮어쓰는 것과 같은 자리, 같은 방식. `cage_ring`·`ring_corners`·gate·걸친 변은 그대로다: 걸친 변이 읽는 겨드랑이 코너(`arm·lo_front`)는 여전히 링 코너이고, 관절만 읽는다.

### rest 대비

## 2026-09-09 (이어서) — 뿌리의 비가 말단까지: 사지 링의 girth

### 룰 3
사지 뿌리 링의 확장·축소를 말단 링으로 전파한다. 원본 비율에 대한 확장비를 **그대로** 넘기는 것으로 충분하다고 정했다 — 링마다 다른 곡선을 둘 근거가 아직 없다.

- **다리 — 폭.** hip → knee → ankle → toe → tip. `L/R knee`·`ankle`·`toe` 링의 `girth` = 고관절 뼈(LeftUpLeg / RightUpLeg 관절). 세 링 모두 `s = side`라 곱해지는 것이 폭이다. `L/R hip` 기둥이 이미 `(1+f)·UpLeg`로 그 뼈를 따르므로 비의 출처가 같다.
- **팔 — 높이.** arm → elbow → wrist. `L/R elbow`·`wrist` 링의 `girth` = 쇄골(LeftArm / RightArm 관절), arm 링과 같은 뼈. `s = up`이라 곱해지는 것이 높이다. 손목 링의 실루엣은 손이 덮어쓴 값이지만 그것도 곱한다.
- **tip 기둥.** `cage_post`에 `girth` 열을 두고 `post_ends`가 `reach`에 비를 곱한다. tip의 `reach`는 가상 endbone에서 `side`로 발가락 폭까지의 오프셋이라 곱하면 뚜껑이 발 정중선 기준으로 넓어진다. `d` 끝(위끝 높이, 평평한 발바닥)은 그대로. 다른 기둥은 빈 girth.
- **손등 이후는 따르지 않는다** — 손 기둥은 빈 girth. 따로 생각할 일로 남긴다.
- **깊이는 곱하지 않는다** — 여전히 깊이 복원 패스의 몫.

## 2026-09-09 (이어서) — 머리는 키를 따른다: girth가 뼈에서 span으로

커밋: (이 항목). 씬은 별도로 — `rebuild cage` 뒤.

### 룰 4
머리 크기는 키에 비례한다. 지금까지처럼 **정면 실루엣만** — head 링의 폭과 crown의 높이. 키는 Head 관절에서 ToeBase까지의 `up` 거리이고 rest 대비 비를 그대로 곱한다. 소아 비례를 생각하면 비선형이어야 하지만 지금은 단순하게.

### 정한 것
- **발은 낮은 쪽.** 두 ToeBase 중 `up`으로 더 낮은 것 — 서 있는 키이고, 한쪽 다리만 편집해도 좌우 응답이 대칭이다. 왼발 하나를 쓰면 `right=0.9`에는 머리가 안 변하고 `left=0.9`에는 변한다.
- **crown 폭도 함께 곱한다.** 요청은 head 폭·crown 높이 둘이었지만 기존 `girth`는 실루엣 네 값을 다 곱하고, crown 폭을 빼면 머리가 위로 갈수록 좁아지는 사다리꼴이 된다. head 링의 오프셋(2.3 cm)도 함께 곱해지는데 작아서 분리하지 않았다. 축별로 갈라야 하면 그때 열을 나눈다. 깊이는 곱하지 않는다.
- **기둥이 따라간다.** `crown mid`·`head mid`의 판 내 오프셋은 링의 `n` reach 그 자체(두개골 높이, 오프셋)다. 링만 곱하면 정중선이 rest 높이에 남아 캡이 접힌다 — probe에서 본 나비 단면의 세로판. `midline()`이 링의 girth를 기둥에 넘긴다. spine 기둥 셋은 링에 girth가 없어 그대로다.

### girth를 span으로
키는 뼈가 아니다. `girth`를 "뼈 하나의 길이 비"에서 **span**으로 일반화했다: `cage_span{ a[], b[], axis, rest }`, 길이 = `max(a·axis) − min(b·axis)`, 비 = 길이 / rest. 뼈는 `a = 관절, b = 부모, axis = rest 방향`이라 FK 아래서 정확히 그 뼈의 길이 — 룰 2·3의 값은 하나도 안 바뀐다. 키는 `a = Head, b = {L, R ToeBase}, axis = up`. 앵커의 `Max`/`Min` 규약과 같은 꼴이다. 관절만 읽으므로 `[N16]`은 그대로다.

코드: `cage_span` 타입, `cage_ring.girth`·`cage_post.girth`·`recipe.girth`가 `cage_span[]`, `girth(jc, span)`은 상수 표를 더 이상 안 읽는다(그래서 `rest_corners`의 부분 상수도 `rings`만으로 돌아갔다). bake에 `bone(joint)`와 `stature`를 두고 레시피가 그것을 적는다. `post()`가 girth를 인자로 받고, `midline`이 `r.girth`를 넘긴다. 새 튠은 없다.

## 2026-09-09 (이어서) — 손목은 손바닥 폭을, 손은 팔의 두께를: `girth_d`

커밋: (이 항목). 씬은 별도로 — `rebuild cage` 뒤.

### 물음
손목 링의 크기가 조절되지 않는다. 팔에서 내려오는 비(쇄골)를 받을 수도, 손가락 첫 마디가 길어지며 벌어지는 것을 받을 수도 있다. 둘 다 받고 깊이 복원에서 열외하는 안도 있다 — 어느 쪽인가.

### 답 — 축마다 근원 하나
손목 링의 두 축은 뜻이 다르다. `s = up`은 팔의 두께이고 룰 3으로 이미 쇄골을 따른다. `d = depth`는 손의 폭(엄지↔새끼)인데 rest 상수라 움직이지 않았다 — 눈에 안 바뀌던 것이 이것이고, 지금의 `girth`는 깊이를 건드리지 않으니 어떤 뼈를 적어도 해결되지 않는다.

정한 것:
- **팔의 모든 링(손가락까지)의 y 두께는 쇄골을 따른다.** 손 기둥 전부의 `d` 끝에 손목 링의 `girth`를 곱한다 — 판이 손목 관절 높이를 중심으로 두꺼워지고 손목 링의 `s`가 같은 비라 둘이 맞닿은 채 간다. 룰 3에서 받아들였던 손목의 두께 단이 사라진다.

- **그래서 손목 이후는 깊이 복원에서 할 일이 없다** — 세 축이 전부 선언됐다.

### `girth_d` — 열외가 아니라 열
"깊이 복원 pass + 손목 열외"가 아니라 깊이도 실루엣처럼 **자기 driver를 선언하는 열**로 두었다. `cage_ring.girth_d`는 `front`·`back` 여유 넷에, `cage_post.girth_d`는 `d_hi`·`d_lo`에 곱한다. `--probe`가 이미 이 값들을 곱해 봤던 자리다. 몸 링의 깊이 복원은 `girth_d = girth`를 적는 일이 되고, `neck mid`·`sternum mid`의 소속 문제는 그 기둥의 `girth_d`에 무엇을 적느냐로 바뀐다. 손목은 두 열이 다른 첫 링일 뿐이다.

### 짚어 둔 것
- 손가락 두께는 마디 길이를 모른다 — 판이 손 전체에 하나라 마디를 늘이면 폭만 넓어진다. 받아들였다.

## 2026-09-09 (이어서) — 깊이 복원 전에: 독립 정의를 가진 정중선 기둥을 걷어내다

커밋: (이 항목). 씬은 별도로 — `rebuild cage` 뒤, `arm lo front`를 0.08로 올린 뒤.

### 계획
1. `sternum mid`의 독립 정의 삭제. v74·v75는 `L/R arm`의 lo_front 둘을 잇는 선분과 정중선의 교점, lo_back 둘의 교점이다. `sternum front`(0.025)는 지우고 arm lo `front`(0.055)에 올려 지금의 흉골 앞을 유지한다 — 겨드랑이 앞 코너도 그만큼 나온다.
2. 양 겨드랑이 앞뒤 네 코너에서 spine 링 네 코너로 직선이 내려가고, spine1·spine2는 자기 관절 높이의 평면이 그 넷을 자르는 중간 링이다. 자기 폭·깊이가 없다.

### 왜 지금인가
두께 driver는 구간 단위로 도착한다(09-07 probe의 나비 단면). 링과 따로 구운 깊이를 가진 정중선 기둥은 곱할 때마다 소속을 따져야 하는 이웃이었고, 깊이 복원(`girth_d`)이 그 기둥들에 닥치기 전에 정의 자체를 없애는 쪽이 낫다.

### 기구 — 걸침 세 단계
걸친 변(`[N21]`)의 일반화. 공통 연산은 교점 하나: `crossing(A, B, axis, plane) = lerp(A, B, clamp01((plane − A·axis) / ((B − A)·axis)))`.
1. **걸친 변** — 교점의 `s`만(spine 링, 기존).
2. **네 귀퉁이 걸침** — `cage_ring.between`(코너마다 정점 둘), 코너 = 교점 그 자체. spine1·spine2: 코너 c = 그쪽 arm 링 lo 코너 c → spine 코너 c.
3. **걸친 끝** — `cage_post.hi/lo_between` + `between_axis`, 끝 = 교점(정중선 기둥은 `side`). `sternum mid`, `spine1 mid`, `spine2 mid`. 구운 오프셋이 없다.

각 단계는 앞 단계까지만 읽는다 — 관절 → 링·기둥 → 변 → 코너 → 끝. `[N16]`의 한 방향 규칙은 그대로다.

### 결과
- sternum의 높이가 Spine3에서 풀린다. rest에서는 거의 같은 높이지만 chest 뼈만 편집하면 이제 겨드랑이를 따른다. 가슴 띠가 구성상 평면.
- spine1·spine2의 폭은 그대로(spine 링이 이미 `hip → 겨드랑이` 선 위), 깊이만 측정값 → 보간값. `spine1/2 front/back` 튠 넷(전부 0이었다)과 `sternum front`, 슬라이더 다섯이 사라졌다.

## 2026-09-12 — 깊이는 자기 폭에서 되찾는다: 복원 패스(룰 8), 그리고 발은 발목에 매달린다

### 요청
두께 복원 패스. 레시피가 끝난 뒤, gate 앞에서, 링마다 레시피가 변형한 변(실루엣)을 기준으로 변형하지 않은 변(깊이)을 고쳐 rest의 비를 되찾는다. 몸통 공유 깊이·절두체처럼 링들이 공유하는 룰은 여기서 적용되지 않는다 — 링마다 독립. 먼저 몸통(spine 셋, 양 arm, 양 hip), 기둥 neck·sternum·crotch의 깊이는 일단 이어진 링들의 평균. 이어서 머리를 뺀 사지 — 손목 이하는 축별 두께가 이미 선언되어 제외, elbow·knee·ankle·toe·tip.

### 설계 — 구간과 기둥 평균 (`[N29]`)
- **구간**(`cage_section`, gate처럼 선언 목록): `hi`·`lo` 정점 무리의 중심 거리(d 직교 성분)가 폭, `by = 폭 / rest 폭`, `front` 정점은 `front_seat` 관절에서, `back` 정점은 `back_seat` 관절에서 d 여유를 `by`배. 링 식의 `g_d`를 선언된 span 대신 **자기 놓인 폭의 비**로 쓰는 것 — 그래서 span으로 적을 수 없는 spine 셋(걸친 변·절두체가 준 폭)도 같은 틀에 든다. 사지 링은 폭이 뿌리 뼈 비라 `girth_d = girth`와 결과가 같지만 선언은 구간 하나로.
- **기둥 평균**(`cage_post.hi_mean`·`lo_mean`): 끝의 d 좌표 = 적힌 정점들의 평균. 요청은 neck·sternum·crotch 셋이었지만 spine·spine1·spine2 mid에도 적용 — 교점(§6 3단계)은 복원 전 코너를 읽었으므로 링이 깊어지면 그 위의 기둥이 따라와야 한다. 대칭 편집에서 교점과 같은 값, rest에서 항등.
- **결정 둘**(승인): 몸통의 자리는 링 중심이 아니라 **Hips**(배 앞·등 뒤 여유의 비가 유지된다), 평균 규칙은 spine mid 셋에도.
- 순서: `ring_corners`+`post_ends` → `between` → **`restore`** → gate. 복원은 depth만, gate 넷은 up·side만 만져 서로 읽는 것이 없다.
- 구간 17: spine·spine1·spine2·L/R arm(Hips), L/R hip(기둥 쌍 — hip ↔ crotch, 그 hip 기둥만 곱하고 crotch는 평균), L/R elbow·knee(자기 관절), L/R ankle·toe, L/R tip 쌍(Foot). 기둥 평균 6.
